# 03 — Сборка страницы Opten в свежем контексте

Результат — вся порученная страница с конечными медиа, нужным поведением и
проверкой. Это роль другого агента после 02. Используются документы проекта;
доступ к истории планирующего чата и клиентским файлам на Desktop не нужен.

## 1. Прочитать пакет и самостоятельно оценить направление

Прочитай `AGENTS.md`, `DESIGN.md`, [процесс](README.md), конкретную ревизию
`VISUAL-DIRECTION.rNN.md`, весь канонический контент и
[медиа-протокол](MEDIA-PROTOCOL.md). Для auth/routes/billing/integration —
`docs/INTEGRATION-CONTRACT.md`; для публичного контента —
`docs/CONTENT-AUTHORING.md`; для Learn/курса — соответствующие контракты.

Приоритет выбора направления: точный путь пользователя → активная ссылка и
область в `DESIGN.md` → единственный относящийся файл после проверки. Не
выбирать между конфликтующими планами только по дате. Если направление
отсутствует, выполнить 02 и передать результат; обычный двухэтапный режим
не разрешает автоматически совместить планирование со сборкой. Прямое
поручение выполнить всё за один раз — отдельное разрешённое исключение.

Проверь актуальные API/варианты, source assets, Git и несохранённые изменения,
маршруты, языки и исходники. Посмотри главную, релевантные страницы/витрину.
Сопоставь план с фактической системой: контент, размеры, шрифты, crop, доступ,
состояния и нагрузку. `READY_TO_BUILD` — старт, а не утверждение готового дизайна.

Рабочие layout/группировку/сцену/иконку можно улучшать по реальному результату
без нового согласования каждой итерации. Сохрани защищённое: исходные факты,
текст, действия, обязательные медиа, бренд и точные пользовательские решения.
Нельзя упростить всё до пустого каркаса только ради скорости.

## 2. Реализовать в текущей архитектуре

- Страница — React/TypeScript в существующем `src/app/pages/`, общие семейства
  — `src/app/components/`. Используй props и текущие варианты.
- Сохрани CSS/Tailwind, текущие локальные variable-шрифты, контейнеры и
  адаптив. Нормальный поток, Grid/Flex; absolute/sticky/transform только там,
  где их оправдывает композиция. Не масштабируй всю страницу и не фиксируй
  одинаковый `100vh` каждому блоку.
- Header/footer/CTA и повторяемые примитивы подключаются реальными импортами.
  Если семейство ещё встроено в старую страницу, адресно извлеки его с
  сохранением вида; не проводи общую миграцию и не делай копию CSS «почти такую же».
- Не добавляй новый стек, готовый starter или конкурирующие UI/animation kits.
  Не превращай каталог в несуществующий product API.
- Публичная индексируемая страница регистрируется для RU/EN, prerender,
  metadata/schema, локализованных ссылок, sitemap и llms по живому checklist
  `docs/CONTENT-AUTHORING.md`. Закрытая/noindex SPA сохраняет свою политику.
  Не меняй extension-locked routes, оплату или доступ в процессе визуальной работы.

Сохраняй существующие пользовательские изменения. Если заказана V2 с
сохранением V1, до общей правки сохрани восстановимые исходники/ассеты и
читаемые снимки. Второй route с импортом тех же mutable-файлов не сохраняет V1.
Не архивировать секреты, кеши и `node_modules`, не делать коммит без поручения.

## 3. Проверить композицию до производства серии

Собери верх с настоящей шапкой и характерную содержательную/рискованную секцию
на реальном тексте. Каркас всей страницы полезен для ритма, но не нужно
закончить весь сайт до первого нового визуала. Для новых медиа временно
допустимы слоты нужного ratio/тона; они не являются финальным результатом.

Если движение влияет на геометрию, уже здесь реализуй минимальный рабочий
сценарий: слои, диапазон, начало/завершение и доступность текста. Посмотри
рендер, проверь загрузку шрифтов, иерархию, оси, переносы и соседние секции.
Не вызывать Image Gen первым действием по одному Markdown-плану.

После этой проверки доведи первый экземпляр каждого нового рискованного
семейства до конечного качества: реальная механика + первый окончательный
визуал + просмотр в секции. Сравни манеру и наблюдаемые критерии с конкретным
REF. Только затем размножай серию и заканчивай всю страницу. Один удачный
Hero не проверяет независимые мокапы, сюжетные иконки и scroll-сцены.

Для слабого места: **наблюдение → целевая гипотеза → изменение → просмотр →
сохранить лучшее или откатить**. Сначала исправь неправильный шрифт/импорт,
не меняй концепцию ради сокрытия технического дефекта. Отсутствие overflow
само по себе не доказывает хорошую композицию.

## 4. Произвести, вставить и проверить медиа

Выполни [MEDIA-PROTOCOL](MEDIA-PROTOCOL.md). Уточни бриф по реальному слоту
перед вызовом, передай доступные визуальные входы, сохрани мастер/итог/промпт,
просмотри отдельно и в контексте. Весь запланированный необходимый объём
должен быть реально получен, вставлен и просмотрен. Пакет промптов, старые
случайные файлы и одна повторённая сцена не заменяют новую серию.

Не объявляй иллюстрацию «готовой», если только написан её filename. Для отмены
необязательного медиа запиши конкретное основание и проверенную альтернативу;
прямо порученную графику нельзя молча отменить. Не выдавай агенто-проверенный
файл за одобренный пользователем.

## 5. Поведение и умеренная нагрузка

Реализуй выбранные состояния и движение полностью: вкладки/FAQ/диалоги/
карусели, hover/focus, появления, связи секций и спокойные участки. Не
добавляй отсутствующие продуктовые функции и не имитируй успешную форму без
настоящей интеграции. Мышь/клавиатура/фокус и возврат работают по паттерну.

Используй CSS, существующий `motion`, Radix/Embla по задаче. Новый движок —
только когда существующие средства не подходят; API проверяются по
установленной версии. Чистые DOM-обработчики, таймеры и observers освобождаются
при unmount/смене маршрута. Разные экземпляры управляют собственными панелями.

Предпочитай `transform`/`opacity` для движения; не измеряй/перестраивай всю
геометрию на каждом кадре. Один контроллер отвечает за свойства слоя. Не
обновляй всё React-дерево каждый кадр, не назначай всему сайту `will-change`
и не делай выразительность из постоянно движущихся полноэкранных blur-слоёв.
Измерения — после нужных шрифтов/медиа и реальных изменений layout.
Декоративные петли/видео/тяжёлые сцены останавливаются вне viewport и в скрытой
вкладке. Фиксированная сложная 3D-сцена может быть заранее отрендеренным видео;
настоящая интерактивная сцена требует соответствующего live-исполнения.

Сохрани смысл и управление при `prefers-reduced-motion`. Прокрутка остаётся
естественной; новый smooth-scroll runtime не вводится ради «плавности».
Невидимый reveal не должен навсегда скрыть важный контент при ошибке.
Для публичного prerender-контента сохраняй осмысленную базовую подачу;
не требуй без-JS работы там, где SPA-контракт её не обещает.

## 6. Проверить фактическую предъявляемую версию

Проверяй через текущий проектный Browser-процесс из `AGENTS.md`: сначала
in-app Browser, Playwright CLI только если он недоступен. Перед запуском
сервера проверить владельца порта; чужой процесс не останавливать.

Обычный проход: 1512px и 390px, узкая проверка 360px для затронутого адаптива;
первая/содержательные/финальная секции и общий footer. Не снимать каждый
`div`. У повторяемых ролей сравни H2, основные описания, карточки, CTA,
eyebrow и оптическое положение иконок. Проверяй реальный crop/силуэт/штрих,
надписи, фон/края, русские и английские переносы, контраст и overflow.
Сопоставь новые семейства с подходящими образцами главной.

Живое движение: вход → прокрутка/действие → остановка → быстрый проход →
возврат; отдельно reduced-motion. Новый autoplay/загрузочный сценарий проверить
в чистом контексте без кеша/предыдущей активации: до проверки старта не
кликать, к нижней сцене прокрутить. Проверяется реальная смена видимых кадров,
а не один `playing=true`. PNG не доказывает плавности. DPR/движок добавляй по
обоснованному риску, эмуляцию не выдавай за физический MacBook/Safari.

После стабилизации выполнить `npm run sync:design-system` и
`npm run verify:design-system`, если изменена библиотека/медиа; затем
`npm run build` и адресные обязательные проверки затронутой функции.
Для локальной сборки допустим `INDEXNOW_SKIP=1` по существующему скрипту.
Vite build проверяет сборку, но не заменяет полноценную TypeScript-проверку;
не заявляй typecheck, если он не запускался. Не создавать CI/огромную матрицу
ради обычной страницы. PageSpeed — только по задаче через глобальный CLI.

При общей правке перепроверь реальные зависимые страницы, включая главную.
При локальной — нужный блок и область влияния. Проверяй именно выдаваемый URL,
текущие CSS/ассеты/HMR; устаревший снимок или ревизионная подпись не являются
доказательством новой версии.

## 7. Сохранить и показать

Убери финальные заглушки/отладочные элементы. Сверь весь контент и действия,
карты медиа и движения с реально показанной страницей. Обнови реальный общий
компонент/вариант и его образец в `src/design-system/catalog.tsx`; производные
инвентари вручную не редактируются. Новую серию снабди областью reuse и
реальной записью происхождения по медиа-протоколу.

Сохрани снимки в `output/playwright/` либо проектном Browser-артефакте,
`REVIEW.rNN.md` с условиями/результатами, значимыми изменениями гипотез и
ограничениями. Свяжи показанную ревизию с восстанавливаемыми исходниками и
ассетами; неизменённый Git SHA без dirty-файлов недостаточен. Показанные
версии не перезаписываются. Обнови запись страницы в `DESIGN.md` на основном
месте. Не заявляй полный успех при известном обязательном остатке.

Финал: результат, адрес/снимок, что проверено, существенные ограничения и
статус `REVIEW_PENDING`. Коммит, push, публикация и Figma-перенос требуют
своего поручения; они не включены в обычную сборку. После комментария меняй
**точный объект → нужное свойство → сохранённые соседи/состояния**, исправляй
причину и проверяй влияние без нового полного 02 для косметики.
