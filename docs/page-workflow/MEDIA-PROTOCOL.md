# Медиа Opten: изображения, интерфейсы и иконки

Общий контракт для 02/03. Директор составляет карту/черновые промпты.
**Генерация, обработка, интеграция и просмотр выполняются только на этапе 03.**
Технический скилл выбранного генератора/редактора читается перед использованием;
этот документ не задаёт несуществующий API или модель.

## 1. Сначала смысл и место

Для каждого слота нужны: section/content-ID, визуальная функция, конкретный
объект/действие, семейство манеры и проверенный образец, реальный размер/ratio,
ракурс/масштаб, фон или alpha, safe crop, область под HTML-текст при наложении,
реальные входные REF и 1–3 наблюдаемых признака качества.

Манера выводится из главной и существующего семейства, включая FeatureCards,
продуктовые интерфейсы, локальные декорации и цветовой язык. Ключевой lime
Opten — `#9CFB51`; не заменять его приблизительным оттенком. Тёмные поверхности
и шрифты проверяются по актуальным исходникам, а не выписываются второй
палитрой в каждом промпте. Не навязывать новому изображению универсальное
зерно, глянец, лампочку или «premium/cinematic/8K» вместо конкретной манеры.

Самостоятельное изображение имеет смысл, а не только закрывает пустое место.
Композиция без картинки допустима, когда закончена и выразительна. Прямо
заказанную графику или характерный язык сайта нельзя массово отменить `NONE`.
Совпадение цвета не делает старый сюжет подходящим к новой теме.

## 2. Выбрать способ получения

| Класс | Правило |
| --- | --- |
| Реальное UI Opten / кейс | Точный screenshot отдельным ассетом; окружение/устройство/рамка отдельно |
| Самостоятельная сюжетная иллюстрация/фото | Генерация под текущий смысл/слот или конкретно обоснованный reuse |
| `UI_VECTOR` | Настоящий SVG текущего согласованного набора/подлинного файла |
| `ILLUSTRATIVE` | Разные смысловые мини-иллюстрации общей манеры, созданные генератором или подходящий подлинный готовый вектор |
| `BRAND` | Подлинные логотипы, постоянные знаки и платформенные marks без генеративной подмены |
| `DATA_GRAPHIC` | Схема/график/таблица/QR по фактам и программной геометрии, не Image Gen |

Обоснование сюжетного reuse: совпадают смысл, качество/формат, допустимое
применение и место в последовательности. Перекраска, отражение и новый crop
того же файла не создают новый сюжет. Логотип, техническая стрелка и один
символ одного понятия могут повторяться; их не перегенерируют ради новизны.

## 3. Изображения с интерфейсом

Если изображение показывает настоящий сайт/popup/результат Opten, используй
реальный UI нужной версии, языка и состояния. Скриншот хранится отдельным
точным файлом. Не отправляй экран на генеративную перерисовку и не доверяй
фразе «preserve exactly» как гарантии сохранения текста/controls.

Для устройства/сцены можно сгенерировать окружение с предусмотренным местом
под экран, затем вставить screenshot в кодовую рамку/маску с корректной
перспективой и пропорциями. Проверь экран, края, стек слоёв, crop и видимый
текст при размере показа. Подлинный качественный мокап предпочтительнее
приблизительно нарисованного устройства. Рамка/подложка/соединители в CSS
не заменяют самостоятельную иллюстрацию там, где нужна именно сцена.

Схематический интерфейс внутри метафорической иллюстрации допустим, когда он
не выдаётся за реальный продукт и не обещает отсутствующие функции/доступ.
Значимые надписи задаются точным списком и проверяются по изображению;
для смыслового текста нужна доступная альтернатива. Основные заголовки,
копирайт, действующие CTA, цены, юридические условия и реальные controls
страницы остаются HTML/React-текстом. Транскрипция не доказывает правильность
надписи, реально нарисованной генератором.

Истинные лица, сотрудники, отзывы, документы, логотипы и результаты клиента
не заменяются вымышленными. Демонстрационная сцена допустима в разрешённой
области и не получает чужую биографию/историю. Не загружай в генератор
сессию, JWT, ключи, личные данные аккаунта или секреты из рабочего screenshot.
Для съёмки используй безопасное демонстрационное состояние без платных операций.

## 4. Единица генерации и лимит попыток

1. Каждая самостоятельная фотография/иллюстрация — отдельный вызов. Для серии
   портретов — один человек на вызов; одна цельная сцена может содержать людей.
2. Лист с последующей нарезкой допустим только для небольших `ILLUSTRATIVE`
   иконок: перечисленные разные смыслы, достаточное разрешение ячейки,
   без подписей/пересечений. Полноценные сцены и портреты не объединяются в лист.
3. Общий стилевой рецепт сохраняется один раз, сцены различаются. Не создавать
   одинаковые изображения с разными именами для фиктивной серии.
4. По умолчанию — одна основная генерация и до двух целевых коррекций на ассет.
   Не обходить лимит переименованием задачи и не повторять одну ошибку сервиса.
   Удачные подходящие результаты сохраняются. Иной бюджет пользователя имеет
   приоритет; новые платные обязательства не добавляются самовольно.

Перед фактическим вызовом обнови промпт по текущему layout. Сцена → манера
по реальным примерам → композиция слота → детали/исключения. Роль REF должна
быть явной: style-only, композиция, точный объект или редактируемый оригинал.
Стилевой референс не является заказом повторить его предмет. Если пользователь
просит «с нуля/без референсов», не передавать старые картинки входом.
Используй поддерживаемый инструментом способ передачи файлов; путь в тексте
промпта не считается переданной картинкой. Не выдумывать выполненный вызов,
seed, модель или недоступный исходник.

Для правки существующего растра сначала просмотреть реальный файл и применить
инструмент редактирования изображений. Технические resize/compress/экспорт
веб-копий сохраняют мастер; они не подменяют редактуру/генерацию.
Не считать фон прозрачным только по промпту — проверить настоящую alpha.

## 5. Иконки и оптика

`UI_VECTOR`: поиск, меню, закрытие, стрелки, chevrons, плюс/минус, check,
play/pause и аналогичные управляющие знаки. Используй реальный Lucide SVG
или существующий предоставленный/project SVG; MUI — только по фактическому
применению, не по одному наличию пакета. Без Image Gen, PNG/WebP, emoji,
трассировки, самодельной перерисовки стандартного paths/CSS и растра внутри SVG.
Большой размер управляющей стрелки не меняет её класс.

`ILLUSTRATIVE` — выразительные смысловые знаки и мини-сцены. Для разных тем
нужны разные подходящие образы общей манеры. Не заменяй такую серию случайным
техническим набором. Подлинный подходящий принятый вектор не перегенерируется
из-за классификации. Новый сюжет не становится постоянным брендовым символом.

Для малого иконного листа после получения: аккуратная нарезка/маска с
сохранением белых деталей, общий холст/keyline/воспринимаемый масштаб и
просмотр ряда на реальном фоне. Прямая прозрачность — когда соответствует
семейству и инструменту; белый фон не удаляется слепо вместе с белым рисунком.

Проверь **слот компонента → полный холст/viewBox → видимый рисунок**.
Диагностируй padding, baseline, flex-shrink, внутренние поля и асимметрию
до локальных translate. Одинаковые квадраты и `place-items:center` не
доказывают оптического центра. Проверенная поправка принадлежит общему
ассету/варианту, а не разным страницам. Сохраняй пропорции, viewBox и
`currentColor` монохромного SVG; слои анимации отделены от оптической коррекции.
У icon-only control есть доступное имя, декоративный знак не озвучивается
дважды. Логотипы не деформируются; ряд платформ проверяется по видимому размеру.

## 6. Графики, схемы и специальные редакционные правила

Точные числа/серии/единицы/периоды и связи берутся из реальных материалов.
Кодовая графика наследует текстовые роли, оси, линии, маркеры, легенду и
проектные интервалы; default-стили библиотеки не являются стилем Opten.
Без данных не придумывай количественный рост. QR создаётся из подлинной
ссылки и проверяется. Основные подписи доступны и редактируемы; не превращай
страницу в один растр/canvas/SVG.

У SEO2 свои более узкие правила в `AGENTS.md` и `seo2/blog-post-instruction.md`:
no-text cover, RU/EN inline с генеративным текстом, Bebas Neue и заданные
редакционные ограничения. Они применяются к SEO2-материалу и не превращают
маркетинговые заголовки или UI новой страницы в Bebas Neue/генеративный текст.
У YouTube-уроков живые remote thumbnails и права источника сохраняются.

## 7. Производство, запись и готовность

Порядок: **настоящий текст/шрифт/компоненты → характерный layout и механика →
просмотр → первый законченный визуал в секции → калибровка → остальная серия →
проверка всей страницы**. Не генерировать наугад первым действием и не ждать
конца всей вёрстки. У каждого нового рискованного семейства свой первый образец.

После получения проверить фактические размеры/ratio/alpha, фон/края,
анатомию/геометрию, надписи и crop. Показать отдельно, затем в правильной
секции/состоянии; серию — рядом. Не растягивать изображение ради слота.
Реальный файл, присутствие в DOM и CSS без скрин-просмотра не закрывают QA.

Финальные веб-файлы: существующее каноническое семейство; для новых обычных
page assets допустим `public/assets/pages/<page-slug>/`. SEO2/Learn/модели
сохраняют свои пути. Мастера и provenance —
`docs/page-workflow/pages/<page-slug>/media/`, необходимые preview-входы
сохраняются локально без секретов. Не хранить большие base64 в metadata.

Один `ASSETS.json` в каталоге страницы содержит записи только о реальных
производственных единицах. Для каждой: `id`, класс/смысл/семейство,
section-ID/использования, источник/метод, реальные prompt/reference inputs,
номер попытки, `masterPath`/`outputPath`, размеры/ratio/alpha, текущий статус,
основание reuse, что действительно просмотрено и замечания. Неизвестное
остаётся неизвестным. Отменённая единица сохраняет причину и проверенную замену.
Отвергнутый файл — история, а не кандидат для молчаливой интеграции.

Статусы производства: `planned → produced → integrated → agent_verified`;
при необходимости `rejected`/`cancelled`. Согласование пользователя отдельно:
`review_pending` или `user_approved` только по явному принятию. В направлениях
02 планируемый slot не является полученным asset-ID. Генерация считается
законченной после получения, вставки и просмотра, не по числу промптов.

Обнови производный inventory через `npm run sync:design-system`, а общий
компонент/семейство и новые варианты — в живом каталоге. Сгенерированный реестр
не редактировать вручную. Provenance и область reuse нового семейства должны
быть доступны из `DESIGN.md`/записи страницы; текущий file inventory не
подменяет происхождение и согласование нового ассета.

При недоступном инструменте или обязательном оригинале назови точный остаток,
продолжи независимую работу, но не называй пустой слот готовой иллюстрацией
и не заменяй её молча случайным старым файлом/stock/CSS-рисунком.
