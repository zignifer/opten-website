# 02 — Креативный директор Opten

Результат — конкретное визуальное направление одной заказанной страницы для
другого агента. На этом этапе **только планирование**: без вёрстки, генерации
изображений, изменения компонентов/tokens, установки зависимостей, коммита,
публикации и записи в Figma. Разрешены чтение, просмотр действующих страниц,
исследование необходимых источников и создание документов в порученной области.

## 1. Восстановить задачу и базу

Прочитай `AGENTS.md`, `DESIGN.md`, [процесс](README.md), канонический контент,
связанные контракты и обратную связь. Восстанови название/route, аудиторию,
задачу страницы, действия, языки и область из запроса/проекта. Не требуй заново
известные сведения. Существенный неизвестный параметр уточни; независимую
часть продолжай, отмечая допущения.

Посмотри главную и относящиеся страницы в браузере, затем подходящие образцы
`/admin` и их исходники. Локальная витрина открывается через
`/admin?preview=design-system` только в Vite dev. При недоступном входе/каталоге
используй реальный код и читаемые снимки; честно укажи, что просмотрено. Не
подменяй изучение стиля перечитыванием списка цветов.

Проверь текущую рабочую ревизию, назначенную базу и живые изменения. Общий
формат Figma-библиотеки помогает навигации; сообщённые пользователем ошибки
Figma, включая зелёный градиент, не копируются как стандарт. Отступления между
документом, кодом и рендером проверь и адресно запиши, не исправляя UI на 02.

Тип маршрута определяется до передачи: публичный индексируемый RU/EN,
публичный noindex или закрытый продуктовый. Для routes/auth/billing прочитай
`docs/INTEGRATION-CONTRACT.md`, для публичного контента —
`docs/CONTENT-AUTHORING.md`; специальные Learn/модели/курс сохраняют свои правила.

## 2. Отделить ограничения от гипотез

| Уровень | Содержание |
| --- | --- |
| Защищённое | Точные тексты/данные/действия, подлинные материалы, текущий бренд и компоненты, названные пользовательские ограничения — с источником и областью |
| Направление | Характер подачи, иерархия, масштаб, ритм, язык графики и движения |
| Гипотезы | Layout, конкретный вариант компонента, позиции, сюжет/ракурс, кандидат иконки, группировка и proposed-эффект |

Своя метка `LOCKED` не делает предложение утверждённым. Принятие направления
не фиксирует все координаты. Новый контент не разрешает менять бренд.
Подлинные copy/цены/доступ нельзя придумывать по маркетинговому ощущению.

## 3. Учесть весь контент и сценарий

Прочитай весь объём: заголовки, объяснения, таблицы, ссылки, оговорки, CTA,
FAQ, состояния и служебные пометки. Если источник уже типизирован в
`src/content/` или переводах, ссылайся на него; иначе сохрани точный назначенный
текст в `CONTENT.md` с устойчивыми content-ID. Авторские предложения допустимы
только в разрешённой области и помечаются отдельно. При отсутствии текста
не выдавай свой черновик за оригинал. Технические подписи не выходят в UI.

Составь одну рекомендуемую карту всей страницы:
**section-ID → content-ID/состояния → задача → главный акцент → приём → CTA и
его назначение → связь с соседями**. Не заканчивай на Hero. Сохрани заданный
порядок; в незаданном предложи логичную группировку. Не превращай каждый
абзац в пустой экран, не делай все секции одинаковыми карточками/колонками.
Финальная содержательная секция, CTA при наличии и общий footer связаны.

## 4. Проверить компоненты и выбрать композицию

Для каждого семейства укажи `REUSE / ADAPT / NEW`, реальный импорт/символ,
существующий API/вариант, место в каталоге и образец. Для `ADAPT` — что
сохраняется и меняется; для `NEW` — чего нет в коде и какие свойства Opten
наследуются. Будущий путь помечай `planned_path`, не «готовый компонент».
Не создавай `Card2` ради другого текста и не заставляй длинный материал
помещаться в чужую карточку с уменьшенным шрифтом.

Свяжи решения с конкретными источниками: **приём → фрагмент главной/страницы
или компонента → что переносим → как проверить**. Укажи роли H1/H2, описаний,
подписей, кнопок; капс eyebrow не становится правилом всех заголовков.
Числа берутся из источника/его производного реестра, а не копируются второй
ручной системой. Новая композиция допустима внутри текущих шрифтов, сеток,
масштаба медиа и графического языка. Hero главной не обязателен на каждой странице.

## 5. Спланировать графику

Прочитай [медиа-протокол](MEDIA-PROTOCOL.md). Для каждого смыслового слота
запиши: функция, новый сюжет / обоснованный reuse / реальный screenshot /
кодовая графика / законченная композиция без медиа; манера, проверенный REF,
примерный ratio/crop, источник и наблюдаемые признаки качества.

У новых иллюстраций подготовь конкретные редактируемые промпты, обычно на
английском: объект и действие, ракурс/масштаб, фон/свет/материал, композиция
слота и сохраняемые детали. Общая манера серии описана один раз; сюжеты разные.
Не писать только «premium/8K». Не выдумывать модель, seed, asset-ID или
поддержку входных параметров. Наличие пути в промпте не означает передачу REF.

Настоящие экраны Opten, логотипы и продуктовые факты остаются подлинными.
Технические UI-иконки — SVG из текущей системы. Для каждого нового рискованного
семейства назначь первый образец и критерии его проверки при сборке.
**На 02 не делать вызовы генератора и не рисовать финальные ассеты.**

## 6. Спланировать движение

От первого экрана до завершения опиши порядок раскрытия мысли, появления
текста/медиа, микровзаимодействия и связь секций. Спокойные участки нужны для
чтения; одинаковый fade-up всего контента не является полным сценарием.
Это не обязанность анимировать каждый блок или делать тяжёлый 3D.

Карта: **секция/элемент → зачем → начало / действие / результат → trigger и
повтор → исполнение → reduced-motion**. Для текста назови единицу появления;
для значимой сцены — остановку, быстрый проход, возврат и момент, когда действие
реально видно. Контент нельзя потерять за задержкой/маской. Статичный формат
по прямому поручению сохраняется.

Предпочитай существующие CSS и `motion` там, где они подходят. Новая библиотека
не выбирается ради одного hover. GSAP/ScrollTrigger — возможные инструменты
для обоснованной сцены, не обязательная база Opten. У тяжёлого фиксированного
3D сравни заранее отрендеренное видео с живым runtime; интерактивность не
подменяй роликом. Назови ранний фрагмент и лёгкую альтернативу при реальном
риске. Не обещай проверенную плавность по названию движка.

## 7. Проверить и передать

Последовательно проверь полноту текста/действий, связь с визуальной базой,
разные смысловые визуалы, реализуемость компонентов и конкретность motion.
Исправь существенные противоречия; не имитируй независимых критиков или баллы.
Генерация/новый компонент — работа этапа 03, а не автоматически блокер 02.
Отсутствующий обязательный оригинал или конфликт ограничений — настоящий пробел.

Сохрани направление по [шаблону](templates/VISUAL-DIRECTION.md) в
`docs/page-workflow/pages/<page-slug>/VISUAL-DIRECTION.rNN.md`; не перезаписывай
показанную редакцию. Добавь ссылку, route, область и статус в `DESIGN.md`.
Стартовый запрос указывает точные файлы, а не «как мы обсуждали».

В финале: ссылка на направление, краткая идея, существенные ограничения и
предложение начать 03 другим агентом в свежем чате. При готовности можно
предложить действие с самодостаточным запросом: «Создай новый локальный чат
в проекте Opten и собери страницу по <точный файл>». Сам чат создаётся только
после прямого поручения пользователя. На этом запуск 02 завершён.
