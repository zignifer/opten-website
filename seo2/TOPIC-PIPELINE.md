# Единый SEO-контур тем

Этот файл описывает только сбор поисковых формулировок и пополнение очереди.
Он не меняет правила написания статей, humanizer или производство изображений.

## Источник истины

`seo2/topic-registry.json` — единственный реестр идей и статусов. Новые
недельные папки и отдельные article brief-файлы больше не создаются.

Статусы:

- `queued` — следующая обычная тема;
- `deferred` — временно отложена и выбирается после всех `queued`;
- `published` — статья опубликована, запись остаётся для дедупликации;
- `parked` — идея требует дополнительных доказательств;
- `rejected` — нерелевантная идея, сохраняется, чтобы не исследовать повторно.

`queueOrder` задаёт стабильный ручной порядок. Новые темы добавляются в конец,
если владелец явно не попросил изменить приоритет.

## Когда проводить исследование

Исследование запускается только вручную:

1. пользователь просит собрать новые темы; или
2. `npm run start:seo` возвращает `start-seo: research-needed`.

Cron, отдельная база, фоновые публикации и автоматическое создание статей
запрещены. Один исследовательский проход лишь предлагает темы; статью создаёт
существующий SEO2-процесс отдельным запуском.

## Ручной проход

1. Запусти `npm run seo:keywords -- --dry-run` и выбери нужные seed-группы из
   `research.seedGroups` в реестре.
2. Собери реальные формулировки Google Suggest:
   `npm run seo:keywords -- --group <name>`. Для глубокого прохода разрешены
   `--alphabet` и `--modifiers`; сначала всегда делай малый проход.
3. Для EN при наличии пользовательской переменной `BING_WEBMASTER_API_KEY`
   добавь `--bing`. Пустой ответ Bing означает `null`, а не доказанный нулевой
   спрос.
4. Для короткого списка RU-фраз используй глобальный навык `yandex-wordstat`:
   сначала `status`, затем `--match both`. Сохраняй broad и exact-like отдельно.
   `totalCount` — месячные показы запроса, не люди, лиды, покупки или рынок.
5. При необходимости посмотри реальные запросы опубликованных страниц через
   `npm run gsc:queries -- 90`. GSC помогает обновлять или расширять уже
   опубликованные кластеры, но не заменяет начальный поиск тем.
6. Для Яндекса проверь реальные запросы сайта через
   `npm run yandex:webmaster:queries -- TOTAL_SHOWS`. Эти данные помогают
   увидеть уже ранжирующиеся URL и не создавать статью, которая каннибализирует
   продуктовую страницу. Источник записывается как `yandex-webmaster`.
7. Нормализуй Unicode/пробелы/регистр, дедуплицируй по `(keyword, language)` и
   сгруппируй формулировки по одной поисковой задаче. Не создавай отдельную
   статью под каждую перестановку слов.
8. Отметь intent: `transactional`, `problem`, `comparison`, `guide` или `info`.
   Отдельно отбрасывай вакансии, зарплаты, пиратские скачивания, чужие login и
   pricing-запросы и темы, которые продукт/курс не решает.
9. Назначь `primaryDestination` по поисковому intent: `/`, `/prompt-library`,
   `/learn` или `/learn/courses/ai-content-marketing-2026`. В ограниченном
   исследовательском батче держи примерно 50/50 между продуктовыми и учебными
   направлениями и распределяй темы внутри каждой половины максимально ровно.
10. Добавь в `topics` только проверенные кластеры. Suggest, Wordstat, Bing,
   GSC, Yandex Webmaster или явно зафиксированное ручное наблюдение должны
   присутствовать в `evidence.sources`. Синтетические seed-комбинации сами по
   себе недостаточны.
11. Запусти `npm run verify:seo-topics`, затем снова `npm run start:seo`.

Временный результат сборщика перезаписывается в
`.tmp/seo-topic-research/latest-keywords.json` и не коммитится.

## Поля новой темы

Каждая тема хранит slug, `queueOrder`, статус, подсказку заголовка, кластер,
intent, buyer stage, `primaryDestination`, RU/EN keyword lock, provenance и
опубликованный URL.
Для каждого ключа отдельно хранятся broad и exact-like volume. Положительное
старое значение нельзя заменять новым `null` или `0`.

RU и EN — две самостоятельные поисковые формулировки. Английский ключ нельзя
получать механическим переводом русского: его подтверждают EN Suggest/Bing или
сохраняют как manual hypothesis. При написании фразы склоняются естественно;
реестр фиксирует semantic coverage, а не обязательную дословную вставку.

## Граница с производством статьи

После выбора темы используются только текущие файлы сайта:

- `seo2/blog-post-instruction.md`;
- `seo2/rules/blog-post-seo-rules.md`;
- `seo2/rules/humanizer-ru.md` и `humanizer-en.md`;
- `seo2/rules/image-style.md` и `seo2/Reference/`.

Исследовательский контур не содержит outline, готовый текст, tone of voice,
visual brief или генерацию изображений. Для каждой статьи по-прежнему создаётся
только production sheet `seo2/visual-plans/<slug>.md` по действующим правилам.

## Секреты

Секреты не хранятся в Git и не попадают в JSON-артефакты. Wordstat использует
пользовательские `YANDEX_CLOUD_API_KEY` и `YANDEX_CLOUD_FOLDER_ID`; Bing —
`BING_WEBMASTER_API_KEY`; GSC уже читает игнорируемый
`.secrets/gsc-oauth.env`. При ошибке разрешено назвать только отсутствующую
переменную, но не её значение.
